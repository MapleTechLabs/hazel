# Hazel UI phase 4: the whole web app on Effect UI

Status: plan v1 (2026-11-27), from branch `t3/hazel-ui-phase4-plan` (based on the spike tip
`9847a07f6`). Builds on `docs/hazel-ui.md` and the contracts in `packages/ui/CONTRACTS.md`.

## Decision (made by the user)

The web app ships fully on Effect UI with no Foldkit left, and no screen exists twice. Every page
is rebuilt from the shared `hazel` vocabulary (semantic primitives, closed options, styles as data),
not ported to Effect UI's HTML builder. A pattern the vocabulary lacks becomes a primitive or a closed
option in the contract, never page styling. The lab (`apps/web-foldkit/src/lab`) and the Foldkit
design gallery (`design.gallery.ts`) are deleted by a separate shell lane, not ported. iOS is not live:
the web is the product, but the vocabulary stays platform-neutral so iOS can follow (every new tag has
an iOS lane and a pending iOS fixture).

## How the move works

Three waves, then the swap:

1. **Contract wave** (this branch): primitives and options for every pattern the pages need.
2. **Foundations and primitives** (parallel): the web renderers of the new tags (lanes `W*`), and the
   app services, island page adapter, parity harness and logic moves the pages stand on (lanes `X*`).
3. **Pages** (parallel, after their dependencies): each lane rebuilds one area as Effect UI components
   in `hazel` under `apps/shared-screens/src/<area>/`, mounts it as an island page in the Foldkit app,
   proves pixel parity against today's page on the offline fixture, makes it the default, and deletes
   the Foldkit page. A screen exists twice only inside its own lane.
4. **Swap** (serial): an Effect UI root replaces Foldkit's runtime and router (`Z1`), then Foldkit
   and its dependencies leave the repo (`Z2`).

Why islands first, not a new root first: the Foldkit app keeps shipping every day of the move; each
page lane can measure parity against the live Foldkit page with a flag; and the risky root questions
(router, history restore, hot reload, code splitting) are proven by a gate (`X0`) early but only bet
on at the end, when every page is already a component.

### Page code that does not change at the swap

A page never talks to Foldkit or to its host directly. It reads its route and the session through
props, and asks the app for things through `Command.Service`s (`X1`):

| Today (`PageOutMessage`, `page/out-message.ts`)                                                                                                   | Phase 4 page                                                   | Island phase layer                                             | After `Z1`                                   |
| ------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- | -------------------------------------------------------------- | -------------------------------------------- |
| `RequestedNavigation` (21 `requestedOrgNavigation`)                                                                                               | `app/Navigate` Command (route, replace, toast)                 | dispatches `ClickedLink` into the root                         | `Router.push`/`replace`                      |
| `RequestedToast` (232 uses in settings, 31 in customers)                                                                                          | `app/ShowToast`                                                | Foldkit toaster                                                | `ToastProvider` (`receives`)                 |
| `RequestedModal` (19 sites, 20 modal kinds)                                                                                                       | `app/OpenModal`                                                | Foldkit modal registry                                         | `ModalProvider`                              |
| `RequestedCommandPalette`, `RequestedTheme`, `SignOut`, `SoundSettings`, `Keybindings`, `CurrentUserRefresh`, `UpdateCheck/Install`, `DmCreation` | one Command each, in `apps/shared-screens/src/app/requests.ts` | the matching root message                                      | the matching provider or service             |
| `Shared` (`page/contract.ts:24`, 15 fields)                                                                                                       | props: the page's own subset (`orgSlug`, `member`, `nowMs`...) | read from the root Model at mount, changes through `Root.send` | `SessionProvider` `shares`, pages `reads` it |

shapes are in `content.ts`; option sets in `options.ts` and `src/style/schema.ts`.

### Resolved without new API

- **Right-click menu on a message** (gap `message-menu-web`): the web renderer builds it from the
  row's `quick` and `actions`, raising `pressReaction` and `action`.
- **Inline edit** (gap `message-edit-inline`): today edits in the composer, not the row
  (`write.ts:539`); `composer.context` covers it.
- **Code highlighting** in `richText` and `codeBlock`: the web renderer runs Prism (as
  `editor/code-highlight.ts`); the language is already data.
- **Pagination** ("Show N more"): a `button` under the list or `list.reachEnd`.
- **Filter builder, bulk selection, j/k keyboard rows:** composed from `popover`, `choiceGroup`,
  `textField`, `button` chips, `table` and `actionBar`; the keys are a page Subscription.
- **Danger zone, inline confirm, type-to-confirm:** `frame` surface `danger`, `dialog` with a
  `textField` (as `apps/shared-screens/src/settings/GeneralSettings.ts`).
- **Token shown once, OAuth or integration connection cards:** `banner` or `frame` with `property`,
  `badge`, `textField` copyable and `menu`. A second page wanting the same card makes it a governed
  composite (the cap is 1; raising it is the user's call).
- **Keyboard shortcut hint bar:** `text` role `kbd` in a `stack`.

  `hazel:page:<id>` off (today) and on (hazel), 390 and 1180 wide, light and dark, a pinned clock and
  reduced motion, runs the entry's `steps` (open a menu, a dialog, a tab), and writes strips
  (today | hazel | diff) to `docs/hazel-ui-screens/phase4/<id>/`.
- **Tolerance:** the islands' bar (`compare-islands.ts`): every residue a channel delta of 5 or less
  (antialiasing); anything else is a bug or a listed known diff with a reason, reviewed by the user.
- **Before deleting the Foldkit page:** the lane commits the "today" strips as the baseline; from then
  on `compare-pages.ts --baseline` diffs the hazel page against them (this is what `Z1` runs).
- **Per primitive:** the `W*` lanes keep the G6 kit diffs (`known-diffs.json`) as today.
