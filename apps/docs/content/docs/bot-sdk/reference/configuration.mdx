Configure your bot with a backend URL for short request/response APIs and a
gateway URL for inbound websocket delivery.

## Environment variables

| Variable      | Required | Default                        | Description                                               |
| ------------- | -------- | ------------------------------ | --------------------------------------------------------- |
| `BOT_TOKEN`   | Yes      | -                              | Bot authentication token                                  |
| `BACKEND_URL` | No       | `https://api.hazel.sh`         | Backend API URL for message sends, command sync, and auth |
| `GATEWAY_URL` | No       | `https://bot-gateway.hazel.sh` | Bot gateway URL for inbound websocket delivery            |
| `PORT`        | No       | `0` (OS-assigned)              | Health server port (Bun only)                             |
| `COMMIT_SHA`  | No       | `unknown`                      | Service version reported in traces                        |

`runHazelBot` and `createHazelBot` also export traces. Locally they go to Effect DevTools; set
`OTEL_ENVIRONMENT` (`local`, `staging` or `production`), `OTEL_BASE_URL` (the OTLP endpoint, required
outside `local`) and optionally `MAPLE_INGEST_KEY` to send them elsewhere. A bot on
[Cloudflare](/bot-sdk/reference/cloudflare) uses its host's tracer instead.

### Example `.env`

```bash
BOT_TOKEN=your-bot-token-here
BACKEND_URL=http://localhost:3003
GATEWAY_URL=http://localhost:3004
```

## `runHazelBot` options

`runHazelBot` reads environment variables by default and lets you override them
in code.

```typescript
interface RunBotConfig<Commands> {
	commands?: Commands
	mentionable?: boolean
	healthPort?: number | false
	layers?: readonly Layer[]
	setup: (bot: HazelBotClient) => Effect<void>
	config?: Partial<HazelBotConfig<Commands>>
	serviceName?: string
}
```

### Example

```typescript
runHazelBot({
	commands: myCommands,
	setup: (bot) =>
		Effect.gen(function* () {
			// Register handlers
		}),
	config: {
		backendUrl: "http://localhost:3003",
		gatewayUrl: "http://localhost:3004",
	},
	serviceName: "my-task-bot",
})
```

## `createHazelBot` options

Use `createHazelBot` when you want to build and manage the runtime directly.

```typescript
interface HazelBotConfig<Commands> {
	botToken: string
	backendUrl?: string
	gatewayUrl?: string
	commands?: Commands
	mentionable?: boolean
	resumeOffset?: string
	sessionStore?: GatewaySessionStore
	stateStore?: BotStateStore
	maxConcurrentPartitions?: number
	heartbeatIntervalMs?: number
	serviceName?: string
	healthPort?: number | false
	logging?: { level?: LogLevel; format?: LogFormat }
}
```

`backendUrl` and `gatewayUrl` default to `https://api.hazel.sh` and `https://bot-gateway.hazel.sh`,
`maxConcurrentPartitions` to `8`, and `resumeOffset` to `"now"` (when no `sessionStore` has a saved offset).

### Example

```typescript
const runtime = createHazelBot({
	botToken: process.env.BOT_TOKEN!,
	backendUrl: "http://localhost:3003",
	gatewayUrl: "http://localhost:3004",
	commands: myCommands,
	maxConcurrentPartitions: 8,
})
```

## Resume and state

The websocket runtime uses two optional stores:

- `sessionStore` persists the last acknowledged gateway offset.
- `stateStore` persists small bot-local state, such as thread mappings.

If you do not provide either store, the SDK uses in-memory defaults. On Cloudflare,
`makeBotSupervisor` keeps both in the Durable Object's storage, see [Running on Cloudflare](/bot-sdk/reference/cloudflare).

## Local development

For local development, point the bot at your local backend and gateway:

```bash
BOT_TOKEN=dev-bot-token
BACKEND_URL=http://localhost:3003
GATEWAY_URL=http://localhost:3004
```
