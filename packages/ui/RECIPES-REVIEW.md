# Recipe review checklist (lane D)

What each recipe must use, per state, so the integrator can check the primitive lanes' recipes
(`src/style/recipes/<tag>.ts`) after merge. Token names are `src/style/tokens.ts`; the seed each row
comes from is in brackets (`ui/` is `apps/web-foldkit/src/core/components/ui/`). A recipe that
needs a colour or step not listed here uses the nearest token and adds a `HAZEL-GAP` row; it never
names a palette step (`palette.*`) or a literal.

## Every recipe

- [ ] Colours are roles, never `palette.*`. Text ink comes from the ladder (`fg`, `fg-3`, `fg-2`) or a
      `*-fg` role; `fg-1` is only for dividers and disabled marks, never readable text.
- [ ] Hover and pressed share one look unless the seed differs; `hover` is emitted under
      `(hover: hover)`, so touch never sticks on it.
- [ ] `disabled` (and `loading` where it applies) is in `inert`, so hover and pressed stop.
      Disabled is `opacity: 0.5` over the resting look (`data-disabled:opacity-50`), not a new colour,
      except fields, which take `muted` as the fill (`ui/input.styles.ts`).
- [ ] Size class: `compact` is the base, `regular` only overrides (the kit's `sm:` value). A kit class
      without `sm:` is the same in both and has no `regular` entry.
- [ ] Transitions use `fast` (150 ms, controls, rows) or `normal` (200 ms, badges, overlays); never
      `slow` for colour. The curve is always `out` (codegen writes it).
- [ ] Focus rings, scale on press, hit areas, forced colours and animations are renderer code
      (`rendererFeatures`), not recipe fields. The renderer draws keyboard focus with `focus-ring`.
- [ ] Type is a role or recipe step (`text`), plus `leading` only where the kit sets a box metric
      (`text-sm/6` is `label` + `leading: "6"`). `code` brings the mono family by itself.
- [ ] `strong` is 500. Kit `font-semibold` (600) has no token yet (see Open questions): use `strong`.

## Open questions (values the seeds could not settle)

1. **Semibold.** Kit headings, the dialog title and the message author are `font-semibold` (600);
   `font.weight` has only `regular` and `strong` (500) and `schema.ts` is frozen. Proposal: a third
   weight or `strong` levels. Until then recipes use `strong` (one weight step light).
2. **Kit `title` heading (18/28, -0.014em)** and the dialog title's compact 18/24 have no role:
   `title` follows the kit's `section` heading (16/24, -0.011em, the level 2 heading). `display` is
   24/32 in both size classes (the kit's `display` has no `sm:` step).
3. **Uppercase eyebrow** (kit heading `label`: `text-xs uppercase tracking-wider`): no text
   transform in `Declarations`; not used by the phase 1 screens.
4. **Mono features**: `code` gets `"zero"` from codegen (`MONO_ROLE` in `scripts/css.ts`), not from
   a token; `font` has no `monoFeatures` field.
5. **styles.css `--accent`** (a grey hover fill) is not a token: `accent-fg` is the brand ink the
   `accent` tone and badge use (`primary-subtle-fg`). Charts, severity and saved-view colours are
   not tokens (no primitive draws them).
6. **`body` at regular** stays 14/20 (the sidebar row, G6-verified); fields, dialogs and
   descriptions use `leading: "6"` for the kit's `text-sm/6`.
